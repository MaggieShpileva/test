# Создание страницы заданий и наград

## 1. Цель

Дать авторизованному пользователю единый экран, где он видит доступные задания сезона, выполняет их и получает бонусы или промокоды. Страница решает проблему разрозненного доступа к механикам вознаграждения: пользователь понимает, сколько бонусов начислено за сезон, какие задания ещё активны и какие награды уже получены.

## 2. Пользовательский сценарий

**Если:** пользователь авторизован и открывает раздел заданий
**Когда:** переходит на страницу заданий (из навигации / по прямой ссылке `/tasks`)  ы
**Тогда:** видит шапку с итогом бонусов за сезон, вкладки «Активные» и «Награды», список активных заданий; может открыть задание, выполнить условие (покупка / условие), забрать награду и просмотреть историю наград.

Краткий успешный путь:

1. Открыть `/tasks`.
2. На вкладке «Активные» выбрать задание.
3. Выполнить условие задания (перейти к покупкам / подтвердить условие).
4. При статусе «выполнено» нажать «забрать награду».
5. Увидеть подтверждение начисления (бонус или промокод).
6. На вкладке «Награды» найти награду в истории.

## 3. Бизнес-логика

- Доступ к странице только для авторизованного пользователя. Без токена — редирект на главную.
- Задания бывают одиночные и групповые (с дочерними шагами и прогрессом `сделано / всего`).
- Типы заданий: заказ (покупка), условие.
- Статусы задания: доступно, в процессе, выполнено (награда ещё не забрана), начислено.
- Тип приза: бонусные баллы или промокод.
- Пока задание в статусе «выполнено», пользователь может явно забрать награду; после успешного claim статус становится «начислено», сумма отражается в сводке сезона.
- Проверка условия может вернуть сразу «начислено» или «выполнено» (с последующим claim — по правилам бэкенда).
- Ошибки проверки: несовпадение класса верификации, rate limit, ошибка интеграции — пользователь остаётся в модалке и видит сообщение об ошибке, задание не закрывается как успешное.
- История наград группируется по месяцам; подгружается постранично при прокрутке.
- У награды есть дата начисления и срок действия (для отображения); у промокода — статусы доставки (ожидание, в пути, выдан, ошибка, истёк).
- Сводка сезона: всего начислено / осталось / уже получено — источник истины с бэкенда; после claim/check UI обновляет локальную сводку согласованно с ответом.
- Старые промокоды (отдельный раздел) не используются: вход в промокоды перенаправляется на задания.

## 4. Поведение

### Общее

- Шапка: заголовок «Задания», подзаголовок «Выполняй задания и получай бонусы», бейдж «За сезон начислено N бонусов», кнопка назад на главную.
- Фон-иллюстрация; отступы/раскладка отличаются для in-app WebView и обычного веба.
- Переключатель вкладок: «Активные (N)» / «Награды».

### Вкладка «Активные»

- **Загрузка (через loader маршрута):** страница появляется с уже подгруженными данными; при ошибке loader — общий error-экран.
- **Список есть:** карточки заданий — иконка, название, краткое описание, дедлайн/оставшееся время, размер награды.
- **Групповое задание:** прогресс и раскрываемый список дочерних заданий.
- **Статус «выполнено»:** кнопка «забрать награду» на карточке.
- **Пусто:** иллюстрация + текст: все задания выполнены, следить за обновлениями.
- **Тап по карточке:** открывается bottom-modal с деталями.

### Детали задания (модалка)

- Показывает название, размер награды, шаги, дедлайн.
- **Бонус / покупка:** CTA «За покупками!» ведёт по URL задания (внешний/внутренний переход).
- **Тип condition:** отдельный сценарий просмотра/получения награды, с учётом статуса доставки промокода.

### Вкладка «Награды»

- **Список есть:** карточки по месяцам — название, тип (бонусы / промокод), дата начисления, срок.
- **Пусто:** иллюстрация + текст: наград ещё не было, выполняйте задания.
- **Догрузка:** при скролле подгружается следующая страница истории.
- **Тап по награде:** модалка с деталями награды (в т.ч. промокод, если выдан).

### После начисления

- Показывается оверлей/экран с суммой бонуса или фактом промокода; закрытие возвращает к списку.
- Счётчик «Активные (N)» и бейдж сезона обновляются без полной перезагрузки страницы.

## 5. Технические требования

- Маршрут: `/tasks`, page-обёртка + Feature `Tasks`, loader `tasksLoader`.
- Без `accessToken` loader делает `redirect('/')`.
- Данные при входе: параллельно список заданий (`GET /v1/tasks`) и первая страница истории бонусов (`GET /v1/bonuses/history` с `limit`/`offset`).
- Действия: `POST /v1/tasks/:id/check`, `PATCH /v1/tasks/:id/claim`.
- Состояние в RTK slice `tasks` (список, summary, history + infinite scroll, claim/check status).
- Типы: `Task`, `TasksListResponse`, `BonusSummary`, `BonusHistoryItem` / группы по месяцам — в `types/api`.
- UI: существующие примитивы и компоненты из библиотеки components-funtech-ui (`Title`, `Typography`, `Button`, `SegmentedControl`, `BottomModal`); ассеты в `src/assets/images/tasks/` (webp), иконки SVG.
- Структура по конвенциям: Feature + вложенные `components/<Child>/`, path aliases, SCSS Modules, `--ui-scale`.
- Прелоад иконок заданий из ответа API в loader.
- Устаревший promocode-route редиректит на `/tasks`.
- Верстка и копирайт — по макету Figma (тексты UI не выдумывать).

## 6. Критерии готовности

**КГ-01 — Доступ только авторизованным**
Если: пользователь не авторизован
Когда: открывает `/tasks`
Тогда: происходит редирект на `/`, страница заданий не показывается.

**КГ-02 — Загрузка списка и сводки**
Если: пользователь авторизован, API отвечает успешно
Когда: открывает `/tasks`
Тогда: видит корректный бейдж «За сезон начислено N», вкладку «Активные (N)» с карточками из ответа и возможность перейти на «Награды».

**КГ-03 — Пустые состояния**
Если: нет активных заданий / нет истории наград
Когда: открыта соответствующая вкладка
Тогда: показывается empty-state с утверждённым текстом и иллюстрацией (не пустой экран и не ошибка).

**КГ-04 — Claim выполненного задания**
Если: задание в статусе «выполнено»
Когда: пользователь нажимает «забрать награду»
Тогда: награда начисляется, статус меняется, сумма отражается в сводке/истории без ручного обновления страницы.

**КГ-05 — История наград**
Если: у пользователя есть награды
Когда: открывает вкладку «Награды» и скроллит вниз при наличии следующей страницы
Тогда: награды сгруппированы по месяцам, догружаются следующие элементы; тап открывает детали.

**КГ-06 — WebView vs web**
Если: приложение открыто в in-app WebView или в обычном браузере
Когда: пользователь смотрит страницу заданий
Тогда: раскладка шапки/контента соответствует варианту окружения (без поломки скролла и табов).

## 7. Вне scope

- Создание или изменение механик заданий на бэкенде (правила начисления, антифрод).
- Админка / CMS для управления заданиями и текстами.
- Push/email-уведомления о новых заданиях или истечении наград.
- Отдельный раздел промокодов (кроме редиректа на `/tasks`).
- Геймификация вне экрана заданий (карта регионов, финальный уровень, каталог продуктов) — без изменений в рамках этой задачи.
- Аналитика событий (если не согласована отдельно).
- Desktop-адаптив сверх уже принятых паттернов проекта / Landscape stub — не расширять без отдельного требования.
- Редизайн навигации приложения целиком; только вход на страницу заданий.
